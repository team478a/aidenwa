# Railway Mock-only 運用テスト手順

## 1. 目的と適用範囲

Railway の本番相当環境で、Web・API・Worker・PostgreSQL・Redisの接続と主要な運用導線を
合成データだけで確認する。Twilio、OpenAI、Zoom Phone、カレンダーなどの外部Provider、
実在する顧客情報、実電話番号、実電話発信は使用しない。

- Web: <https://sales-aiweb-production.up.railway.app>
- 対象環境: Railway `production`（Singapore）
- VoiceProvider: `mock`
- 外部連携フラグ: すべて `false`

## 2. 管理者アカウント

### 現在の状態

Railway環境には、リポジトリ共通の既定パスワードはない。`admin@example.local`などは
ローカル開発seedの既定メールアドレスであり、Railwayのログイン情報ではない。

本番相当環境では開発seedの実行が禁止されているため、最初の組織管理者は、承認された
一回限りの初期管理者作成手順で作成する必要がある。パスワードをGit、Railwayのビルド引数、
ログ、スクリーンショットまたはこの文書へ記録してはならない。

初期管理者は`pnpm db:bootstrap-admin`で一度だけ作成する。このコマンドは、既存ユーザーまたは
既存組織が一件でもある場合は失敗し、同時実行をDBロックで防ぎ、作成結果を監査ログへ残す。
パスワードは標準出力にも監査ログにも記録しない。

1. 合成データ専用の組織slug、管理者メールアドレス、12文字以上の一時パスワードを決める。
2. Railway APIサービスのPrivate Consoleで、次の変数を現在のConsoleセッションにだけ設定する。
   Railwayサービスの永続変数には保存しない。
   - `BOOTSTRAP_ADMIN_CONFIRM=CREATE_INITIAL_ADMIN`
   - `BOOTSTRAP_ORGANIZATION_NAME`
   - `BOOTSTRAP_ORGANIZATION_SLUG`
   - `BOOTSTRAP_ADMIN_NAME`
   - `BOOTSTRAP_ADMIN_EMAIL`
   - `BOOTSTRAP_ADMIN_PASSWORD`
3. `pnpm db:bootstrap-admin`を一度だけ実行する。出力には組織IDとユーザーIDだけが表示される。
4. Consoleセッションを閉じ、上記の一時変数が残っていないことを確認する。
5. 初回ログイン後にパスワードを変更する。
6. 作成日時、実行者、対象組織、ユーザーIDだけを運用記録へ残す。パスワードは残さない。

禁止事項:

- Railwayで`pnpm db:seed`を実行しない。
- `.env`、GitHub、Issue、PR、チャットへパスワードを保存しない。
- PostgreSQLへ平文パスワードまたは独自生成したハッシュを直接書き込まない。
- 既存ユーザーまたは組織がある環境でbootstrapの制約を回避しない。

## 3. 事前確認

テスト開始前に次のすべてを確認する。

- RailwayでWeb、API、Worker、PostgreSQL、Redisがすべて`Online`。
- 公開URLにアクセスすると「管理画面にログイン」が表示される。
- APIとWorkerにはPublic Domainがない。
- `VOICE_PROVIDER=mock`。
- `PRODUCTION_CALLS_ENABLED=false`。
- Twilio、OpenAI、Zoom、カレンダー関連の有効化フラグがすべて`false`。
- テストに使う企業名、担当者名、メール、電話番号、CSVがすべて架空。
- テスト担当者と実施時刻を記録する。

推奨する合成データ識別子は`SMOKE-YYYYMMDD-HHMM`とする。電話番号は外部へ接続されない
Mock環境でのみ、明らかなテスト値（例: `05000000001`）を使用する。

## 4. 操作テスト

### 4.1 ログイン

1. 公開URLを開く。
2. 承認済みの初期管理者メールアドレスとパスワードを入力する。
3. 「ログイン」を押す。
4. 管理画面が表示され、画面上のユーザーroleが`admin`であることを確認する。

期待結果: ログインが成功し、企業、CSVインポート、シナリオ、キャンペーン、模擬通話、
商談予定などの管理メニューが表示される。

### 4.2 企業・担当者・電話番号

1. 「企業」を開き、`SMOKE-... 株式会社`を登録する。
2. 作成した企業を開き、架空の担当者を追加する。
3. 種別`phone`の架空電話番号を追加する。
4. 種別`fax`の架空FAX番号も追加する。
5. FAX番号が架電対象として選択できないことを確認する。

期待結果: 企業、担当者、番号が保存され、FAXは架電対象外になる。

### 4.3 タグと営業リスト

1. 「タグ」で`SMOKE-...`タグを作成する。
2. 作成した企業へタグを付与する。
3. 「営業リスト」で同じ識別子のリストを作成する。
4. 作成した企業を営業リストへ追加する。

期待結果: タグと営業リストに対象企業が一件表示される。

### 4.4 CSVプレビュー・取込み

実在情報を含まないUTF-8 CSVを使用する。例:

```csv
name,phone
SMOKE CSV株式会社,05000000002
```

1. 「CSVインポート」でCSVを選択する。
2. プレビューで列マッピングと件数を確認する。
3. 取込みを実行する。
4. 同じCSVを再度プレビュー・取込みし、二重登録されないことを確認する。
5. 既存企業・番号と重なるデータでは、重複候補の理由が表示され、自動マージされないことを確認する。

期待結果: 初回だけ登録され、再実行は冪等。CSV原本や行データが監査ログへ残らない。

### 4.5 商材・AI担当者・シナリオ

1. 「商材」で合成テスト用商材を作成し、必要なバージョンを公開する。
2. 「AI担当者」でMock用担当者を作成し、必要なバージョンを公開する。
3. 「シナリオ」で合成テスト用シナリオを作成する。
4. 開始、案内、結果などの最小ノードを設定し、検証後に公開する。

期待結果: 公開済みの商材、AI担当者、シナリオがキャンペーンで選択できる。

### 4.6 キャンペーンとMock架電

1. 「キャンペーン」で合成テスト用キャンペーンを作成する。
2. 公開済み設定と営業リストを指定する。
3. 対象プレビュー、対象確定、検証、承認、開始の順に進める。
4. 「Mock qualified」を一回実行する。
5. 「模擬通話」でジョブが完了し、結果が`qualified`相当になっていることを確認する。

期待結果: 外部通信や実発信を行わず、Mock結果、通話イベント、利用量、監査ログが記録される。

### 4.7 フォローアップ

1. 「AI会話・引継ぎ」またはフォローアップ一覧を開く。
2. Mock通話から生成された引継ぎタスクを確認する。
3. 管理者として担当割当、開始、完了など利用可能な状態遷移を確認する。
4. 完了理由には`SMOKE-...`を含む合成テスト理由を入力する。

期待結果: タスク状態と監査履歴が更新され、Zoom Phoneへの外部同期は実行されない。

### 4.8 予約

1. 「予約設定」で合成テスト用の予約ポリシーを作成する。
2. 「商談予定」でMock対象企業の予約枠取得、仮押さえ、確定を実施する。
3. 同じ枠の重複確定が拒否されることを確認する。

期待結果: 内部予約が作成され、外部カレンダーには送信されない。

### 4.9 監査ログと安全性

1. 「監査ログ」で今回の企業作成、CSV取込み、設定公開、キャンペーン開始、Mock実行、
   フォローアップ、予約の記録を確認する。
2. `before_data`と`after_data`にパスワード、Cookie、セッション、CSRF、APIキー、
   CSV原文・正規化行がないことを確認する。
3. 外部Provider利用量と実電話発信件数が0であることを確認する。

## 5. 結果記録

秘密情報や合成CSV内容を添付せず、次だけを記録する。

| 項目                  | 記録内容                    |
| --------------------- | --------------------------- |
| 実施日時              | Asia/Tokyo                  |
| 実施者                | 氏名または承認済み識別子    |
| Release commit        | Railwayへ配置したcommit SHA |
| Railway deployment ID | Web / API / Worker          |
| サービス状態          | 5サービスのOnline確認       |
| 操作結果              | 4.1〜4.9のPASS/FAIL         |
| 外部Provider呼出し    | 0であること                 |
| 実電話発信            | 0であること                 |
| 残課題                | FAIL、回避策、再試験条件    |

## 6. 中止条件

次のいずれかが発生したら操作を止め、Gate AをNo-Goのままにする。

- VoiceProviderが`mock`以外になっている。
- 外部連携フラグが一つでも`true`。
- 実在する顧客情報または電話番号が入力された。
- APIまたはWorkerにPublic Domainが設定された。
- 組織境界、権限、FAX禁止、オプトアウト、監査マスキングのいずれかが機能しない。
- Web、API、Worker、PostgreSQL、Redisのいずれかが不安定またはOffline。
